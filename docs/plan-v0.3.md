# v0.3 实施计划：Mac 端与同步

本文是 v0.3 的实施依据和进度记录，用法同 plan-v0.1/v0.2。

依据：[product-spec.md](product-spec.md) §5、[schema.md](schema.md) §6/§7、[decisions.md](decisions.md) D-12 至 D-15、D-20。

## 0. 背景与并行约束

- 2026-09-27 决定提前开工（用户确认）：v0.2 的真机验收与日常使用并行进行，用户随用随反馈，v0.2 问题修复优先于 v0.3 新进度。
- Mac 端与手机端同一 Flutter 工程（`app/`），macOS target 已由模板生成；数据层（drift）跨平台复用。
- 耦合点只有一个：同步要求手机端先有 `change_log`（V3-M1 是手机侧数据层改动，纯代码+单测，不影响在用功能）。
- 开发机即 Mac，V3 里程碑大多可本机验证，不占用真机会话。

## 1. 目标与完成标准

v0.3 做三件事：**手机数据自动同到 Mac 保存完整副本；Mac 用模型生成周报回传手机；加密备份可恢复。** 完成标准 = product-spec §7 中标注 v0.3 的验收场景在双端通过。

## 2. 技术要点与候选

| 事项 | 方案 / 候选 | 备注 |
|---|---|---|
| Mac 常驻菜单栏 | tray_manager + window_manager | 先小样验证；不行换 system_tray 或推迟到窗口应用可用之后 |
| 局域网发现 | bonsoir（Bonjour/mDNS）| 候选；不行退回手机扫码里带 IP 直连 |
| 配对 | Mac 显示二维码（含设备 ID、地址、公钥指纹），手机 mobile_scanner 扫码 | D-13 |
| 传输通道 | 本机 HTTP（shelf）+ 配对时交换的密钥做双向认证与内容加密 | 具体加密方案实施 V3-M2 时定案并记录（自签 TLS 证书固定 vs 应用层加密）|
| 变更传输 | 按 change_seq 逐条发送逐条确认，连续游标推进（schema §7.2/§7.3，第一版不合并）| |
| 附件 | 先报 sha256，对方缺才传，校验后确认；depends_on_blob 完成前变更不确认 | schema §7.4 |
| macOS 上的插件 | 手机专属插件（health、image_picker、通知等）按平台隔离，Mac 主入口不初始化 | |

## 3. 里程碑

- **V3-M0 Mac 端跑通：** macOS 构建运行；Mac 专属主页（副本概览骨架：消息数、记录数、同步状态占位）；平台分流（main 按平台走不同初始化，Mac 不碰 iOS 专属插件）；菜单栏常驻小样。本机验证。
- **V3-M1 变更日志（手机侧）：** `change_log` 建表 + `generation` 生成与持久化；业务写路径（消息、修订、附件索引/关联、资料、记录、版本、来源、健康数据、建议处理状态）同事务追加变更；单测：change_seq 无空洞递增、负载与 entity_version 一致（不可变修订引用）、代次更换。
- **V3-M2 配对与通道：** Mac 起本地服务 + 显示配对二维码；手机扫码（mobile_scanner）建立配对（peers 表双端落库、密钥固定）；加密与双向认证定案并记入本文；未配对设备拒绝。
- **V3-M3 增量同步：** push 协议（逐条发送/确认、acked_contiguous_seq、断点续传、代次变化处理）；附件哈希传输；Mac 接收端写库（副本只读，D-12）；同一 WiFi 自动同步（P-30/P-35 的第一版：应用在前台时发现即同步）。
- **V3-M4 Mac 查看与同步状态：** Mac 端只读浏览消息流与日视图（复用手机组件）；同步状态页（最后成功时间、待传数量、立即同步、错误）。
- **V3-M5 周报分析：** Mac 端模型配置（复用 V2-M1 组件，配置不同步）；周报生成（D-20：手动/每周定时、失败保留上一份、事实链接来源）；分析结果与修正建议回传手机；过期提示（D-14）；手机接受/拒绝建议（接受生成 confirmed 新版本）。
- **V3-M6 加密备份与恢复演练：** 按文件清单生成加密备份（D-15）、校验通过才算可用；恢复演练一次并留证据。
- **V3-M7 双端联调验收：** product-spec 中 v0.3 验收逐条执行，证据入 platform-matrix。

## 4. 风险与注意

- **手机是唯一编辑者（D-12）：** Mac 端一切写入仅限副本表、分析结果与修正建议；代码层面用只读仓库隔离，防止误写。
- **change_log 埋点覆盖面：** 漏埋的写路径 = 永远同步不到。上线前用"全表行数 vs 变更覆盖"清点一次；新写路径的代码评审必查。
- **v0.2 反馈优先：** 用户在用手机端，反馈的 bug 修复插队。
- **周报的数据边界（D-20）：** Mac 分析走用户配置的模型，调用记录可查；外部 agent 入口默认关闭。
