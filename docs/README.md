# 设计文档索引

本目录汇总项目的当前设计。`me_talk.md`、`claude_talk.md`、`codex_talk.md` 是讨论记录。

**维护规则：** 讨论得出的结论要及时写进本目录。用户的最新指示优先：用户新提出的要求即使还没写进本目录，也以用户的指示为准，并尽快补进文档；文档与用户指示不一致时，按用户指示修改文档。

| 文档 | 内容 | 维护规则 |
|---|---|---|
| [requirements.md](requirements.md) | 用户提出的需求（R 编号） | 只记录用户说过的内容，并注明出自哪一轮 |
| [decisions.md](decisions.md) | 实现建议与设计决策（D 编号） | 每条写明理由、替代方案，以及被否决时的影响 |
| [product-spec.md](product-spec.md) | 版本范围、页面、交互流程、验收场景 | 每个体验版本交付前，先在这里定好范围 |
| [schema.md](schema.md) | 数据模型：实体、字段、状态、时间语义 | 改动数据结构前先改这里 |
| [platform-matrix.md](platform-matrix.md) | 各平台能力的实现与验证状态 | 只凭验证证据更新状态 |
| [plan-v0.1.md](plan-v0.1.md) | v0.1 实施计划、任务进度、新会话上手指引 | 任务完成后在清单勾选；验证证据仍记入 platform-matrix |

## 编号约定

- `R-xx`：用户需求，来自 `me_talk.md`，或用户在对话中直接提出（标注为"5 补充"等）；
- `D-xx`：设计决策，由 Claude 或 Codex 提出；
- `A-xx`：验收场景，定义在 `product-spec.md`；
- `P-xx`：平台能力项，定义在 `platform-matrix.md`。

编号一经分配不复用。某条作废时，标记为"已废弃"并注明原因，不删除。

## 当前审核事项

- `codex_talk.md` 4_reply / 5_reply 是对应旧版本的审核，不应照搬为当前需求。
- RV-03 中围绕“原件及全部派生数据彻底删除”的要求，以及同步删除 Mac、清除历史备份等要求，因本轮范围澄清退出当前设计，不能继续作为原件清理的阻塞项。
- 手机副本清理不使历史记录过期，不触发恢复代次变化。完整备份恢复和同步可靠性仍是独立事项，在各自交付阶段处理。
- 5_reply 中与删除无关的剩余问题已在 0.5 修订，Codex 7_reply 复核通过；7_reply 的两条实现约定（v0.2 批次不并发、v0.3 变更包版本一致）已写入 schema §3.1a、§7.2，在各自版本实现时执行。
- v0.1 已进入实施阶段，计划和进度见 [plan-v0.1.md](plan-v0.1.md)。后续审核以实际代码和验收结果为主。
- 所有平台项仍未经真机验证，文档结论不等于功能完成。
