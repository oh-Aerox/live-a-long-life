# 产品规格

本文按功能领域定义页面、交互流程和验收场景。需求编号见 [requirements.md](requirements.md)，决策编号见 [decisions.md](decisions.md)，各平台实现与验证情况见 [platform-matrix.md](platform-matrix.md)。

## 1. 产品一句话

一个本地优先的个人健康记录应用：每天主动问你一两句，你用文字随手回答，病历和检查单从病例夹、体检导入；手机健康数据自动补充；电脑负责整理和分析。数据保存在你自己的设备上，只按你的配置发送给你选择的模型服务或备份位置。

分析是**纵向**的（R-37）：基于长期积累的饮食、运动、睡眠、心情、压力等生活数据，结合疾病与体检数据看趋势和关联。单次就医或体检数据经提取核对后进入这套纵向分析，产品不提供"解读这一份报告"的独立功能。

## 2. 平台分工

| 平台 | 角色 |
|---|---|
| iPhone | 主要的记录端：日常记录、每日回顾、健康数据、病历与检查单、主动咨询 |
| Mac | 分析与归档：完整副本、周报、修正建议、加密备份、只读查看病例与健康档案、主动咨询 |
| 安卓 | 手机端适配中 |
| Windows | 电脑端适配中 |

只用手机录入（R-23）；手机和电脑在同一局域网内自动同步（R-24）。真机读取健康数据、重签覆盖安装后数据保留、安卓与 Windows 的适配项，验证结果记录在 [platform-matrix.md](platform-matrix.md)。

## 4. 首次使用与基本资料

- **首次使用引导：**
  - 确认时区；
  - 设置每日回顾时间（R-11）；
  - 可选填写基本资料，每项都可以跳过（D-18）。
- **基本资料**（R-15）：出生年月、生理性别、身高、运动偏好、慢性病、过敏、长期用药等，逐步收集，每项都可以跳过。

## 5. 日常记录

- **对话页：**
  - 发送文字，可以连续发多条；
  - 对话页不添加照片和文件（D-48）。照片和 PDF 从病例夹/体检入口导入，仍写入消息流、走 D-10 去重；已有的附件消息照常显示；
  - 每条消息发送后立即保存，并显示"已保存"；
  - 应用发出的问题（回顾提示语）也以消息的形式显示在对话流里；
  - 消息按时间排列，按天分组显示，可以往上翻看历史。
- **普通消息纠错：** 误录可编辑并保留历史，误发消息可确认后从对话流移除。共享附件仍被其他消息引用时不删除文件；仅在无引用且没有提取记录时，可随误发内容一并清理。医疗原件的空间管理单独处理（见第 10 节），不为普通消息移除设计医疗字段级联清除。
- **"记好了"按钮：** 表示"这次说完了"，并触发一次整理（见第 7 节）。
- **离线可用：** 录入和保存没有任何网络依赖。

## 6. 每日回顾

- **提醒：** 本地通知，在设定的时间弹出，点击后进入对话页。可以设置多个提醒时间，也可以关闭。
- **只问缺的**（D-08、D-09）：已经记过的、设备已有数据的不再问；用户说过"没有"的视为已回答；跳过的问题当天不再出现；一次回顾最多问 3 个。

## 7. 自动整理与按日查看

- **整理批次**（D-05）：由"记好了"、短暂无输入、每日回顾触发，把消息整理成记录。没有配置模型或整理失败时，消息显示"待整理"，其他功能照常可用，模型恢复后自动补整理。
- **记录类型：** 饮食、睡眠、心情、身体不适、运动、其他。
- **时间归属**（R-10、D-06）：比如"昨天晚饭吃了面"会归到昨天，记录时间是现在。"今天""昨天"按自然日理解，明确说出的日期不会被改写。归属日期不是今天时，在对话流里提示"已记到 9月25日"。凌晨说"今天晚饭吃了面"这类有歧义的情况，先记到前一天，提示"已记到 9月25日，对吗？"，点一下即可改。
- **按日视图：** 日历或日期切换，显示当天的记录、设备数据和缺口。每条记录可以点开查看来源消息。
- **修正记录：** 修改后状态变为"用户已修改"，保留修改历史；用户改过的字段不会被再次整理覆盖，冲突以修正建议的形式出现，同一冲突反复出现时转为"需要手动处理"。不要的记录可以删除，删除时可以选择连原消息一起删。
- **日视图从几点开始**（规划中）：设置项，默认 00:00。习惯熬夜的人可以设为 04:00，凌晨的记录就显示在前一天的日视图里。只影响显示，不修改记录的日期。目前只有默认值，设置入口尚未实现。

## 8. 模型

- **模型配置**（R-27、R-28、D-16）：服务预设（OpenAI / Claude / DeepSeek / 自定义 OpenAI 兼容 / Ollama 等）→ 填 key → 选模型 → 测试连接。标注能力和数据边界（本机、局域网、云端）；本地模型不可用时任务排队，不改走云端。
- **模型调用记录：** 在设置里可以查看每次调用发送了什么、返回了什么。

## 9. 健康数据

- **读取健康数据**（R-16、R-17、D-11）：睡眠、步数、体能训练、活动能量，只读取，不写入。授权前先说明用途。
- 健康数据只作为补充（R-18）；用户亲口说的内容优先（R-19），不被设备数据覆盖。
- 未授权或读不到时显示"暂未读取到记录，可手动补充"，回顾照常询问。

## 10. 病历与检查单

- **病例夹与体检入口**（D-27）：在"健康档案"中提供"我的病例夹"与"我的体检"两个入口（体检报告是独立 doc_type），可添加（拍照/相册/PDF，仍写入消息流并走 D-10 去重提示）、查看列表与详情、发起提取与核对。
- **导入与提取：** 拍照或 PDF → 保存原件 → 模型提取 → 逐项核对（D-04）。
- **指标记录：** 项目、数值、单位、参考范围、检查日期，并能定位到原件的页码或区域。
- **近似重复提示**（D-10）。
- 一份多页报告可以由不同消息中的照片组成，页序可以调整。
- **历史医疗记录：** 报告描述其检查/就诊日期的事实。康复、复查和新结果追加为新记录，不修改过去的诊断与指标；识别错误仍可纠错并保留历史。
- **检验项目索引**（D-27，schema §5.3）：每个检验项目冗余一行（项目、数值、参考范围、检查日期、核对状态、来源），随记录版本自动重建，供按项目查历史数值（趋势视图与后续分析的数据基础）。
- **指标趋势与就诊时间线：** 同一检验项目按检查日期画出变化曲线；就诊时间线按时间排列症状起始时间、你的描述、做过的检查、相关报告。
- **长期状况档案**（R-36、D-25）：从就医、体检信息中区分临时疾病（感冒发烧等，只影响近期建议）与长期状况（结石、囊肿、糖尿病、肩周炎、结节、过敏等），长期状况记入档案、复查追加不改写；分类由模型建议、用户核对。
- **人体图：** 按身体部位汇总需要关注的内容（仍异常的检验数值、报告里的异常描述、未解除的身体状况、近期身体不适），每条都能跳回原文件。

### 医疗原件空间清理

- **清理手机原件，保留记录**（R-32、R-34、D-22）：入口在医疗文件详情和"设置 → 医疗文件空间"。按实际文件去重展示占用，默认选择已提取、已核对报告；不包括文字消息和日常饮食照片的批量清除。
- 预览本次可释放的空间、影响的文件和引用数量、其他设备原件保存情况。正在导入、提取或传输的文件先跳过。没有已知其他副本时说明原件可能无法再查看，用户可取消、先归档或明确继续。
- 清理成功后只释放手机大文件和缓存，诊断、指标、日期、来源索引、文件指纹及核对状态不变。Mac 与备份继续保留已有原件，已生成分析不因空间清理过期。
- 手机查看数据无需原件；需对照原件时可主动从 Mac 取回，或重新提供同一文件。匹配哈希后沿用附件和记录，不重复建档。普通后台同步不会把清理过的文件自动下载回来。
- 原件不可用时明确显示，未核对字段仍保持未核对；取回后可以继续核对。界面不把单文件取回叫作"恢复健康数据"，也不要求用户运行整库恢复。

示例确认文字："将清理手机上的 12 份医疗文件，释放约 180 MB。历史医疗记录保留，Mac 上的已归档原件不受影响。"按钮为"清理手机原件"和"取消"；只有缺少其他副本或未完成核对时才补充相应说明。

## 11. 主动咨询

- **主动咨询入口**（R-38、D-26）：用户可临时向默认模型提问；默认最小上下文、发送内容入调用记录；咨询不进消息流、不参与整理。长期状况档案存在时回答能利用它。

## 12. 电脑端与同步

- **Mac 应用：** 常驻菜单栏，接收同步，保存完整副本（D-13）。
- **扫码配对；同步状态页**（最后一次同步时间、待传数量、"立即同步"按钮）。同步可断点续传，不产生重复记录或附件。
- **周报分析**（R-35、D-20）：由 Mac 应用通过已配置的模型生成，遵守数据边界，调用记录可查看。手动触发；失败时保留上一份并可重试。每条事实陈述都链接到来源记录和原始消息。周报除总结外给出下周在饮食、运动、睡眠等方面的建议。
- 分析结果回传手机；分析范围内的数据有新增、修改、删除时，提示"需要更新"（D-14）。
- **修正建议：** Mac 提出，手机上接受或拒绝（D-12）。
- Mac 保存已接收并校验的附件作为档案，通告文件可用状态；手机清理不联动删除 Mac 副本（D-22）。
- **规划中：**
  - 周报每周定时自动生成；
  - Claude Code / Codex skill 作为调用 Mac 应用分析命令的适配器；让外部 agent 直接读取数据需要用户在设置里主动开启，默认关闭。

## 13. 备份与恢复

- **导出与恢复**（手机端）：
  - 导出为一个文件夹：`data.json`（全部消息、修改历史、附件关联、用户资料，以及回顾时间等设置；不含模型配置和 key）、`files/`（附件原件）、`manifest.json`（每个文件的 SHA-256 和大小、消息数量、导出时间、格式版本）；
  - 导出完成后自动校验：逐个核对文件哈希，结果显示为"已导出 N 条消息、M 个文件，校验通过"；
  - **从导出恢复：** 在设置里选择一个导出文件夹，先校验清单，再导入。应用里已有数据时，先提示导出现有数据，用户明确选择"替换全部数据"后才继续，不做自动合并。替换的实现方式：先在临时位置校验并准备好新资料库，成功后一次替换，失败则保留原资料库不动。缺失或损坏的文件单独列出，其余内容照常导入，结果显示"部分恢复"，不标成完整恢复；
  - 导出文件夹没有加密，导出时提示"导出的内容未加密，请保存在安全的位置"。
- **加密备份与恢复演练**（D-15，电脑端）：按文件清单生成，校验通过后才成为可用备份；恢复时列出缺失的文件。
- **备份到云服务**（R-26）：规划中，尚未实现。目前备份固定存放在电脑的"文稿/长命百岁备份"目录，不能选择位置，也不会上传到 iCloud 等云服务。

## 14. 隐私

- 数据保存在设备本地，没有应用自己的服务器（R-25）；同步只在局域网内进行。
- 发给模型的内容按用户配置的服务发送，每次调用都可在调用记录中查看。
- 未核对的内容不作为事实参与分析。

| A-14 | 回顾只问缺的 | 午饭已经记过、设备有睡眠数据，回顾时不问午饭，睡眠只问感受 | 每日回顾 |
| A-15 | 同步重试不重复 | 同步中途断开 WiFi，重连后续传完成，Mac 上没有重复记录或附件 | 电脑端与同步 |

| A-17 | 周报可溯源 | 每条事实陈述可找到对应历史记录与来源索引；原件可用时能打开，手机已清理时显示位置和取回入口，不能伪称原件仍在本机 | 电脑端与同步 |
| A-18 | 备份可恢复 | 用备份在另一个环境中恢复，消息、已归档附件、记录符合清单；Mac 备份期间清理手机副本不影响归档原件。未归档文件明确列为缺失。恢复后新代次同步不遗漏、不重复 | 备份与恢复 |
| A-19 | 检查单核对 | 导入一份真实的检查单，关键字段在核对前不作为事实参与分析；每个数值都能定位回原件 | 病历与检查单 |
| A-20 | 医疗原件清理保留历史 | 一份已提取并核对的检查报告清理手机副本后，文件占用实际减少；指标、诊断、日期、核对状态、记录版本和来源索引不变。重启后仍可查看数据，分析不因清理过期 | 病历与检查单 |
| A-21 | 按需补回原件不重复建档 | A-20 后主动从 Mac 取回或重新上传同一报告，校验后沿用同一个附件与医疗记录，页码来源可打开；未取回时普通同步不自动下载。Mac 不可达时仍可读提取数据 | 病历与检查单 |
| A-23 | 日期不被改写 | 9/26 01:30 分别发送："今天一点才睡着" → 记为 9/26 01:00；"9月25日晚饭吃了面" → 记为 9/25；"今天晚饭吃了面" → 记为 9/25，并提示"已记到 9月25日，对吗？"。只提到日期、没说时刻的记录，没有被编造出具体时刻 | 自动整理 |

## 16. 交互原则

1. **先保存，再理解。** 任何输入先落盘，模型可用与否不影响保存。
2. **不催促，不积压。** 跳过的问题不变成待办；漏记几天后可以自然地接着用。
3. **不把推断当事实。** 未核对的内容有标记；读不到数据时显示"未读取到"，不显示"无"。
4. **每条结论都能找到出处。** 分析结果能点回历史记录和来源索引，原件不在本机时如实显示可用位置。
5. **每天的回答控制在一分钟以内。** 回顾问题一般一到三个。
6. **记录和提示，不做诊断。** 出现异常情况时，建议是"咨询医生"，不输出疾病概率。
