# v0.4 实施计划：病历与检查单

本文是 v0.4 的实施依据和进度记录，用法同 plan-v0.1/v0.2/v0.3。

依据：[product-spec.md](product-spec.md) §6、[schema.md](schema.md) §5/§8、[decisions.md](decisions.md) D-04、D-10、D-22、D-23、D-24。

## 0. 背景与并行约束

- v0.3 双端联调验收已于 2026-09-28 完成。用户日常在用手机端 + Mac 端，v0.2/v0.3 的反馈 bug 修复继续优先于 v0.4 新进度。
- 提取管线与脱敏（D-23/D-24）是本版新定的两条决策，实现必须与之对齐；发现决策与实际冲突时先改决策再改码。
- OCR（Apple Vision）在 Mac 上可直接本机验证，手机侧导入/核对 UI 需真机会话；**真机验收需要真实检查单/病历样本**，需要用户提前准备几份（照片和 PDF 各有；最好含不同医院格式）。
- v0.3 遗留项处置：**mDNS 自动发现排入本版 V4-M5**（原件取回依赖 Mac 可达，Mac 换 IP 要重配对的问题在取回场景会放大）；周报每周定时生成、D-14 按依赖范围精算、Mac 端 generation_changed 完整重建、Mac 修正建议独立传输管道——继续顺延，不进 v0.4。

## 1. 目标与完成标准

v0.4 做三件事：**检查单/病历导入后能提取成可核对、可溯源到原件位置的指标记录；医疗历史只追加不改写，并有趋势与就诊时间线；手机原件可清理释放空间、记录保留、按需取回。** 完成标准 = product-spec §7 中标注 v0.4 的验收场景（A-19、A-20、A-21、A-33～A-36）在真机通过，另补验 A-17/A-18 的"手机已清理"场景。

## 2. 技术要点与候选

| 事项 | 方案 / 候选 | 备注 |
|---|---|---|
| PDF 文字层探测与抽取 | 候选：syncfusion_flutter_pdf / pdfx；或 platform channel 走 PDFKit | 有文字层直取；扫描件逐页渲染成图走 OCR（D-23） |
| 本地 OCR | Apple Vision `VNRecognizeTextRequest`，platform channel，iOS/macOS 复用 | 输出文本+bounding box；文档级识别（表格）在新系统上可选启用，老系统降级 |
| 页筛选 | 按页打分：保留/丢弃锚点关键词 + "数字+单位+参考范围"数值密度；默认筛选、用户可改 | D-23；检查文字报告（所见/结论）与总检建议必须保留；只影响发送副本 |
| 脱敏 | 三层：锚点标签取邻值 / 18 位身份证校验位正则（含易混字符归一化）/ 用户姓名全文替换 | D-24；占位符替换，坐标映射保留；单测用固定脱敏用例集 |
| 结构化 | 默认模型纯文本调用；OCR 文本带行索引，要求返回 JSON 且每字段引用行索引 | 映射回坐标写 `lab_panel.locator`；解析容错沿用周报的经验（中转站非严格 JSON） |
| 多模态兜底 | 显式入口 + 裁剪提示；裁剪候选 image_cropper | D-24；裁剪副本临时文件，发送后即弃 |
| 指标趋势图 | 候选：fl_chart | 同一 item_name（后续 item_code）按检查日期连线 |
| mDNS 发现 | bonsoir（v0.3 候选未验证） | 不行退回手动输入地址 |

## 3. 里程碑

- **V4-M0 数据层与提取管线基础：** `medical_documents` 建表（pages 有序多附件、doc_type、exam_date/report_date、review_status，schema §5.1）；`lab_panel` 记录类型落地（schema §5.2/§3.5）；PDF 文字层探测与直取；Apple Vision OCR platform channel（文本+坐标），扫描 PDF 渲染成图走同路径。单测 + Mac 本机验证。
- **V4-M1 脱敏、页筛选与结构化提取：** D-24 三层脱敏 + 占位符坐标映射 + 调用记录记遮蔽项数；D-23 页筛选规则打分（保留/丢弃锚点 + 数值密度，只影响发送副本，被排除页 OCR 文本保留可补提取）；结构化提示词（要求逐字段行索引引用）与解析容错；结果写 `lab_panel`（全部 unreviewed）+ locator 坐标回映射。脱敏固定用例集单测（含 OCR 易混字符、日期不误伤）；页筛选用真实体检册样本单测（数据页不误杀、"所见/结论"与总检建议保留）。
- **V4-M2 导入与逐项核对 UI：** 医疗文件导入入口（拍照 / 相册 / PDF）；多页组文件与页序调整（不同消息的照片可组成一份文件），每页缩略图带页筛选的"已排除"标记、点选可恢复（D-23 默认筛选+用户可改，不静默丢弃）；逐项核对页——五个关键字段（项目、数值、单位、参考范围、检查日期）confirmed/edited 后才作为事实参与分析（D-04）；点数值定位回原件页码并高亮区域（A-19）；近似重复提示：检查日期+检查项目相同时提示"可能重复"（D-10）。
- **V4-M3 多模态显式识图兜底：** 医疗文件详情"用模型识图"入口；调用前裁剪提示与系统裁剪界面，裁剪副本仅发送不落库，可跳过但提示风险（D-24）；模型不支持图片时按 D-16 能力标注提示，不报保存失败。
- **V4-M4 历史医疗记录与趋势/时间线：** 康复、复查、新结果追加为新的带日期记录，既往诊断与指标不变（R-34/A-35），识别错误仍走已有纠错保留历史；指标趋势视图（同项目按检查日期）；就诊时间线（症状起始、用户描述、检查、相关报告）。
- **V4-M5 手机原件清理与按需取回：** 入口在医疗文件详情和"设置 → 医疗文件空间"（D-22/schema §8）；按实际文件去重展示占用，默认选已提取已核对，正在导入/提取/传输的跳过；清理预览（可释放空间、影响文件与引用数、其他设备副本状况；无已知副本时说明后果，可取消/先归档/明确继续）；清理成功 → 副本状态 offloaded，只释放文件与缓存，事实/核对状态/来源索引/指纹不变，失败不报告已释放；从 Mac 取回（沿用同步通道，哈希校验，沿用附件 ID）与重新上传同一文件匹配补回（D-10），普通同步不自动下载回来；共享文件只清理一次、占用只计一次（A-34）；**mDNS 自动发现**（bonsoir，失败退回手动输入地址）。
- **V4-M6 双端联调验收：** A-19～A-21、A-33～A-36 逐条真机执行，A-17（周报溯源的已清理场景）、A-18（备份的手机清理场景）补验，证据入 platform-matrix。

## 4. 风险与注意

- **脱敏范围是用户明确定的（只删姓名+证件号）：** 医师姓名、医院名、流水号不在删除范围；不要擅自扩大，也不要因规则简单而漏掉三层中的任何一层。规则漏网的最终兜底是"裁剪提示 + 用户核对"，不是承诺零泄漏。
- **OCR 与结构化都会错：** 拍照歪斜、表格错位、手写内容识别质量不保证。所有提取结果 unreviewed，未核对不算事实（D-04）——这条是安全网，UI 上不能为省点击绕过。
- **清理是删除性操作：** 严格按 schema §8 的状态表执行；正在提取/发送的文件必须跳过（D-05 校验表里"附件本地文件暂不可用"分支会依赖这个）；确认文件真正移除后才更新状态与已释放空间。
- **真实样本依赖用户：** 各医院报告版式差异大，锚点词表和结构化提示词要用真实样本调；提前向用户收集样本，避免联调时才发现覆盖不足。
- **v0.2/v0.3 反馈优先：** 日常使用发现的 bug 修复插队。
