## 1. 目标与完成标准

v0.1 只做一件事：**在 iPhone 上可靠录入，退出、重启、更新、恢复后数据都不丢。** 不含模型整理、健康数据功能、同步、分析、Mac 端。

完成标准 = 以下验收在真机 iPhone 上全部通过，并在平台矩阵留下证据：

| 验收 | 内容 |
|---|---|
| A-01 | 多图分段不丢失（强制退出后仍在，顺序和附件归属正确） |
| A-02 | 飞行模式下离线录入 |
| A-03 | 同一 PDF 导入两次，重复提示三选项符合 D-10 |
| A-04 | 发送中强制退出，消息不丢也不重复 |
| A-05 | 提醒可设置、可关闭，重启手机后仍有效 |
| A-06 | 修改消息后可查看原文 |
| A-07 | 重签并覆盖安装后数据保留 |
| A-29 | 导出后在新环境恢复，内容一致；已有数据时必须明确选择替换；缺附件显示"部分恢复" |

**v0.1 期间并行的技术验证**（不属于 v0.1 功能，但要在这个阶段跑通，结果写进平台矩阵）：
- HealthKit 真机读取试验（P-10 的前置：免费签名下申请权限、anchored query 读到睡眠样本即可）；
- 一键重签安装脚本（P-50）；
- 签名到期前的应用内提醒（P-52）。

## 2. 技术选型

框架为 Flutter（D-01，已采纳）。以下是候选依赖包，**采用前先在真机小样验证，不满足就换并在本文记录**：

| 用途 | 候选 | 备注 |
|---|---|---|
| SQLite | drift | 类型安全、自带迁移；备选 sqflite |
| 本地通知 | flutter_local_notifications | 需验证：多个时间、重启后仍触发（A-05） |
| 多图选择/拍摄 | image_picker（多选用 pickMultiImage） | 需验证一次多选 |
| PDF/文件导入 | file_picker | |
| SHA-256 | crypto（流式计算） | 大文件不整块读入内存 |
| 路径 | path_provider | 附件存 Application Support 下 `files/` |

工程约定：固定 bundle ID 和签名 team（D-19，免费账号 App ID 有数量限制）；仓库用 git 管理，工程初始化时 `git init` 并首次提交（当前目录还不是 git 仓库）。

## 3. 数据层范围（schema 的 v0.1 子集）

v0.1 建表：`messages`、`message_revisions`、`attachments`、`attachment_copies`、`message_attachments`、`profile_fields`、`settings`。

实施要点：
- §1.1 通用字段全部保留；`change_seq` 允许为空（`change_log` 到 v0.3 才建）；
- 消息修改历史按**被替换文字原来的修订号**保存，从 0 开始（schema §2.2）；
- 附件先落盘、SHA-256 校验通过后才标 `present` 并显示"已保存"（§2.3a）；文件按哈希命名存放；
- 消息用 `client_msg_id` 幂等写入（D-10），发送中断重试不产生重复（A-04）；
- 误发消息用 `deleted_at` 标记并使 `version` 加 1（§2.1）；
- 数据库迁移脚本从 v0.1 开始编号，之后只追加迁移，不改旧迁移。

## 4. 实施步骤

按顺序交付，每步结束时应用都处于可运行状态：

- **M0 工程初始化：** flutter create、固定 bundle ID、git init 与首次提交、目录结构（`lib/data` 数据层、`lib/ui` 界面、`docs/evidence/` 验证证据）、真机跑通空应用（验证免费签名流程）。
- **M1 数据层：** 建表迁移；消息、附件、修订历史的读写仓库；客户端 UUID 幂等；单元测试覆盖：幂等写入、修订号规则、附件校验状态机。
- **M2 对话页（核心）：** 消息流按天分组显示、上翻历史；连续发多条文字；一次选择或拍摄多张照片；导入 PDF；附件复制进应用存储并校验后才显示"已保存"；SHA-256 重复提示（查看已有 / 仍然添加 / 取消）；"记好了"写入 done_marker。对应 A-01 至 A-04。
- **M3 消息纠错：** 编辑消息保留历史（A-06）；误发消息确认后从对话流移除；共享附件仍被其他消息引用时不删文件（product-spec §3）。
- **M4 通知与设置：** 首次使用引导（时区确认、回顾时间、可跳过的基本资料，D-18）；本地通知（多个时间、可关闭、重启有效，A-05）；设置页；签名到期提醒（D-19）。
- **M5 导出与恢复：** 导出文件夹（data.json 含消息、历史、附件关联、资料、设置 + files/ + manifest.json）、导出后逐文件校验；恢复：校验清单 → 空资料库直接导入，已有数据时明确选择"替换全部数据" → 临时位置准备好新库后一次替换，失败保留原库 → 缺件显示"部分恢复"。对应 A-29。
- **M6 真机验收：** 逐条执行 A-01 至 A-07、A-29，截图或录屏存 `docs/evidence/`，更新平台矩阵状态。
- **T1（并行）HealthKit 试验：** 免费签名下开 HealthKit capability，真机申请睡眠读取权限，用 anchored query 读到样本，结果记入平台矩阵。
- **T2（并行）重签脚本：** 一条命令完成重签安装（P-50）；覆盖安装后验证数据保留（A-07）。

## 5. 交付检查（Codex 7_reply 提出）

- 保存过程被打断不丢内容（A-04）；
- 更新（覆盖安装）后数据保留（A-07）；
- 恢复后能继续录入、修改，重启后仍在（A-29）；
- 恢复失败时原资料库不受影响。

## 6. 风险与注意

- **免费签名 7 天过期**（D-19）：开发期间保持固定 team；到期用 T2 脚本重签，不卸载重装。
- **iOS 权限文案：** 相册、相机、通知在首次请求前说明用途；HealthKit 文案在 T1 一并准备。
- **大文件复制耗时：** 多图和大 PDF 的落盘校验异步执行，界面显示进度，校验完成前不显示"已保存"。
- **候选包差异：** 每个候选包先做真机小样，不满足（尤其通知重启后失效、图片多选上限）就换，并更新本文第 2 节。
